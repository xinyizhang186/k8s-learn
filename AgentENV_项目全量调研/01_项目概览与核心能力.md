# AgentENV：项目概览与核心能力

> 调研日期：2026-08-31  
> 范围：AgentENV 官方 `latest` 文档、GitHub `kvcache-ai/AgentENV` 主仓库与 Releases。  
> 版本提示：当前 GitHub 最新 tagged release 为 `v0.1.2`；`main` 分支 Rust workspace 已为 `0.1.3`。`latest/main` 中的内容不一定全部包含在 v0.1.2 二进制发布中。

## 1. AgentENV 是什么

AgentENV 是一个 **Self-hosted Agent Sandbox Runtime**。它为 AI Agent 动态创建可执行 Shell、代码、工具与服务的隔离 Linux 环境。

每个 Sandbox：

- 拥有独立 Guest Linux Kernel；
- 拥有独立文件系统、进程和网络；
- 可执行命令、上传/下载文件；
- 可 Pause / Resume / Snapshot / Fork / Delete；
- 可从 OCI Image、Template 或 Snapshot 启动；
- 可通过 Proxy 暴露 Sandbox 内 HTTP/SSE/WebSocket 服务；
- 可通过 E2B SDK/API 调用。

## 2. 为什么不是普通 Docker Sandbox

| 维度 | 普通容器 | AgentENV |
|---|---|---|
| Kernel | 与 Host 共享 | 每 Sandbox 独立 Guest Kernel |
| 隔离边界 | namespace/cgroup | Firecracker microVM |   一个是进程级隔离，一个更接近虚拟机级隔离
| OCI Image | 常先完整拉取/解包 | 支持块级按需加载 |
| VM Memory Snapshot | 无 | 有 |
| 增量 Snapshot | 非核心原语 | 核心能力 |
| Fork | 需额外设计 | 原生工作流 |
| Agent API | 自行封装 | E2B compatible |
| 分布式 | 常完全依赖 K8s | 自带 Gateway/Scheduler，可部署在 K8s |

## 3. 解决的关键问题

### 大量环境镜像

Agent benchmark / RL 可能需要大量不同 OCI Image。AgentENV 让本地磁盘更像**有界缓存**，而不是预先保存全部镜像。
“有界”就是：缓存大小有限制。  完整环境放远端，本机只缓存当前真正需要的数据。
```text
OCI Registry / Snapshot Store
          ↓
      Remote blocks
          ↓
       OverlayBD
          ↓
      Local cache
          ↓
   Firecracker rootfs
```

### 快速启动与恢复

Agent rollout 经常从同一状态反复启动。AgentENV 使用 Firecracker Snapshot 保存 VM/Memory 状态。官方公开口径强调 snapshot-backed boot/resume 可进入约 50ms 以内量级，pause 可进入约 100ms 以内量级。

这些是公开性能口径，不应未经自身硬件复测直接当成 SLA。

### 不可信代码隔离

microVM 为每个 Sandbox 提供独立内核边界，更适合模型自动生成的不可信代码。

### 高密度

相同 Snapshot 的只读内存块可借助 Host Page Cache 共享。README 还给出过约 9.6x memory overcommit 的生产口径，但真实值取决于 workload、dirty rate、memory reclaim、NUMA 与缓存命中。

## 4. 与 E2B 的关系

AgentENV 不是 E2B 本身，而是提供 E2B-compatible API：

```bash
export E2B_API_URL=http://127.0.0.1:8000
export E2B_SANDBOX_URL=$E2B_API_URL
export E2B_API_KEY=$AENV_API_KEY
```

上层可以继续使用 E2B SDK，把实际 Runtime 指向自托管 AgentENV。

## 5. 典型业务

- Agent 代码执行；
- Agentic RL rollout；
- benchmark/eval；
- 软件工程 Agent；
- Browser/Tool Agent backend；
- 临时开发环境；
- 快速 reset/fork 的搜索探索任务。

## 6. 技术栈

- Runtime：Rust
- HTTP：Axum
- VM：Firecracker
- Virtualization：KVM；另有 Experimental PVM    给 microVM 提供底层虚拟化能力
- Guest control plane：envd     在 Sandbox 内执行命令、管理文件/进程
- Storage：OverlayBD + ublk
- Object storage：OpenDAL/S3-compatible
- Distributed services：Go
- RPC：gRPC/Protobuf    多个服务之间需要通信。
- Binding store：memory / Redis
- K8s discovery：EndpointSlice
- P2P：iroh / iroh-blobs

## 7. 核心工程价值

```text
microVM isolation
+ OCI on-demand loading
+ layered block storage
+ VM/disk incremental snapshots
+ lifecycle orchestration
+ E2B-compatible API
+ ingress/egress control    ingress 是外部怎么访问 Sandbox，egress 是 Sandbox 能访问外部哪里。
+ distributed scheduling
+ P2P artifact transport
```

## 8. 成熟度

已有 release、安装脚本、Docker/K8s 部署、分布式控制面、测试体系和 API 兼容层；但项目仍快速演进，PVM/P2P 等能力带 Experimental 属性。生产环境应固定 tag/commit/kernel/config 后验证。

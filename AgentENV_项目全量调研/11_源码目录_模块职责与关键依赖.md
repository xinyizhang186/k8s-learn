## 3. Runtime 主链

### `src/api/`

- Axum HTTP Router
- E2B compatibility
- request/response
- authentication
- Proxy
- generated types

### `src/orchestrator/`

Sandbox 生命周期编排核心：

```text
create/start/pause/resume/snapshot/fork/delete/cleanup
```

### `src/sandbox/`

Sandbox abstraction + Firecracker 实现。

### `src/snapshot/`

Snapshot metadata、VM state、memory artifact、disk layer、repository、restore/publish。

### `src/template/`

OCI/Dockerfile Template Build，环境与资源定义。

### `src/image/`

Image resolve、OCI Registry、conversion、cache、on-demand path。

## 4. `storage/`

```text
storage/
├── overlaybd/
├── ublk/
├── ublk-daemon/
├── uffd-core/
└── util/
```

- `overlaybd/`：分层块设备、VirtualFile、read/write/snapshot restack。
- `ublk/`：用户态后端映射为 Linux block device。
- `ublk-daemon/`：ublk service。
- `uffd-core/`：保留的 userfaultfd 相关替代实现；当前并非主 workspace 路径。

## 10. 推荐源码阅读顺序

### 第一遍：主链

```text
src/api
→ src/orchestrator
→ src/sandbox
```

### 第二遍：存储

```text
src/image
→ storage/overlaybd
→ storage/ublk
→ src/snapshot
```

### 第三遍：网络

```text
sandbox network
→ src/api/proxy.rs
→ egress policy
```

### 第四遍：分布式

```text
services/gateway
→ services/scheduler
→ Redis binding
```

### 第五遍：高级能力

```text
src/p2p
custom_extension_api
warm-pool
benchmarks
```

## 11. 最值得追的一条调用链

```text
POST create sandbox
→ API handler
→ Orchestrator
→ resolve Template/Snapshot
→ create block devices
→ create network
→ Firecracker config
→ start/restore
→ envd ready
→ response
```

读通这条链就建立了项目的主要心智模型。

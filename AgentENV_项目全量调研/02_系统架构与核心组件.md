# AgentENV：系统架构与核心组件

> 调研日期：2026-08-31  
> 范围：AgentENV 官方 `latest` 文档、GitHub `kvcache-ai/AgentENV` 主仓库与 Releases。  
> 版本提示：当前 GitHub 最新 tagged release 为 `v0.1.2`；`main` 分支 Rust workspace 已为 `0.1.3`。`latest/main` 中的内容不一定全部包含在 v0.1.2 二进制发布中。

## 1. 总体架构

```mermaid
flowchart TB
    C[Agent / E2B SDK / aenv CLI]
    G[Gateway :8080]
    S[Scheduler :9090 gRPC]     :9090 gRPC 表示 Scheduler 提供的内部通信接口使用：
    A[AgentENV Node API :8000]
    O[Orchestrator]
    F[Firecracker microVM]
    E[envd]
    U[ublk]
    B[OverlayBD]
    LC[Local bounded cache]     本机只缓存当前真正需要的数据块。
    R[OCI Registry / POSIX / OSS]    OCI Registry → 镜像仓库    POSIX 一般指 POSIX 文件系统接口/本地文件系统形式的存储。      OSS 一般指：Object Storage Service，对象存储服务。

    C --> G
    G <--> S
    G --> A
    S --> A
    A --> O
    O --> F
    F --> E
    F --> U
    U --> B
    B --> LC
    LC --> R
```
Gateway → 根据调度结果把请求转发给 Node
Scheduler → 需要知道 / 管理 Node 的调度信息
Orchestrator 理解为：Sandbox 创建过程的“总指挥”。
Firecracker 才是真正把 Sandbox 虚拟机运行起来的东西。
envd 运行在 Firecracker 创建出来的 Guest microVM 里面。
Artifact 直译是：产物 / 制品
在工程里，而是：系统运行、构建、训练、评测过程中生成或需要传输保存的数据产物。

单机模式可直接访问 Node API，不必经过 Gateway/Scheduler。

## 2. API Server

路径：`src/api/`    src/api/ 是 AgentENV 里专门负责“对外提供接口”的模块。

职责：

- E2B-compatible HTTP API；
- Sandbox lifecycle；   
- Template/Snapshot；
- authentication；
- Sandbox Proxy；
- generated API types。     API 请求和响应对应的数据结构。

HTTP 框架使用 Axum。

## 3. Orchestrator

路径：`src/orchestrator/`

核心链路：

```text
create request
→ allocate sandbox identity/resources
→ resolve template/snapshot/image
→ prepare block devices
→ prepare network
→ configure Firecracker
→ boot/restore
→ wait envd ready
→ Running
```

并负责 pause/resume/snapshot/fork/delete/cleanup。

## 4. Firecracker Sandbox

主要路径：

```text
src/sandbox/
src/sandbox/firecracker/
thirdparty/firecracker-client/
```

负责 vCPU/memory、rootfs、TAP、Guest Kernel、boot、pause/resume、snapshot/restore。

## 5. Guest envd

主要依赖：

```text
thirdparty/envd/
src/sandbox/
```

envd 是 Guest 内控制服务，承担命令、文件、进程、readiness 等操作。`secure=true` 时需要独立 `envdAccessToken`。

## 6. RootFS 数据链路

```text
Firecracker /dev/vda
       ↓
      ublk
       ↓
   OverlayBD
       ↓
Writable Upper
       ↓
Snapshot Layers
       ↓
Base OCI Layers
       ↓
cache / registry / snapshot store
```

读取从新层向旧层寻找目标块；写入当前 upper。创建 Snapshot 时 seal upper，使其成为 readonly lower，再打开新 upper。

## 7. Memory Snapshot

```text
Firecracker VM memory
        ↓
dirty/present ranges
        ↓
process_vm_readv
        ↓
memory snapshot layer
        ↓
ublk read-only block device
        ↓
snapshot/cache
```

相同 Snapshot 的多个 Sandbox 可利用 Host Page Cache 复用只读内存页。

## 8. 网络

```text
Host namespace
    |
 veth-{slot}
    |
Sandbox netns
    |
  vpeer
    |
   TAP
    |
Firecracker VM
```

网络层负责地址分配、namespace、TAP/veth、host interaction、egress policy、DNS/host resolver 与 Proxy。

当前 main 默认地址规划可见：

- host interaction：`10.11.0.0/16`
- veth：`10.12.0.0/16`
- TAP link：`169.254.0.20/30`

部署时必须检查网段冲突。

## 9. Proxy

支持 HTTP、SSE、WebSocket。

Header 路由示例：

```http
x-agentenv-sandbox-id: <sandbox-id>
x-agentenv-target-port: <port>
```

也支持域名模式：

```text
{port}-{sandboxID}.{domain}
```

## 10. 分布式控制面

```text
Client
  ↓
Gateway :8080
  ↓
Scheduler :9090 gRPC
  ↓
AgentENV Nodes :8000
```

Gateway 负责入口、转发、聚合与 binding lookup；Scheduler 负责 node discovery、health、placement、sandbox→node binding、resource filtering 和 artifact peer discovery。

# AgentENV：测试、持久化、可观测性与故障排查

> 调研日期：2026-08-31  
> 范围：AgentENV 官方 `latest` 文档、GitHub 主仓库与 Releases。  
> 版本提示：tagged release 与 `main/latest` 请分开理解。

## 1. 测试层次

建议理解为：

```text
Unit
→ component
→ integration
→ E2E API
→ distributed
→ benchmark/load
```

仓库当前可见：

```text
tests/common/
tests/integration/
tests/integration.rs
tests/orchestrator_integration.rs
crates/e2e-tests/
crates/test-support/
crates/benchmarks/
```

## 2. Sandbox 测试

官方 Developer Internals 中的 Sandbox 测试关注：

- Firecracker binary；
- kernel；
- tools image；
- user image/rootfs；
- boot args；
- vCPU/memory；
- runtime policy；
- log paths；
- envd version。

常见验证：

```text
boot
process execution
file I/O
network
pause/resume
snapshot/restore
orchestrator integration
```

## 3. Template Builder 测试

要验证：

- Dockerfile instructions；
- ENV/ARG/WORKDIR/RUN/USER；
- rootfs；
- rebuild；
- snapshot commit；
- readiness。

尤其不能假设“支持 Dockerfile”就等同于完整 Docker daemon/BuildKit。

## 4. 持久化目录

```text
Persistent root: /var/lib/aenv
Runtime state:   /run/aenv
Dependencies:    $AENV_HOME/deps
```

官方 Persistence Artifact Inventory 还提醒 Sandbox token seed 属于持久化/备份范围。

## 5. Backup 范围

建议确认：

```text
snapshot repository
metadata
token seed
node identity
local persistent state
configuration
secret references
```

`/run/aenv` 一类 runtime path 应按 transient 处理。

## 8. `/dev/kvm` 故障

```bash
ls -l /dev/kvm
```

可能原因：

- BIOS/UEFI virtualization 未开；
- Host 不支持 nested KVM；
- kernel module；
- permission；
- cloud provider 限制。

PVM 仅应在合适云环境下单独评估。

## 9. KVM Permission

```bash
id
ls -l /dev/kvm
getent group kvm
```

确认 AgentENV Runtime 用户属于相应 group/capability。

## 10. ublk

```bash
lsmod | grep ublk
sudo modprobe ublk_drv
```

具体模块与权限以 Host Kernel/官方 installer 为准。

## 11. 启动慢排查

按完整关键路径拆：

```text
image resolve
→ registry/remote block
→ cache
→ block device
→ Firecracker
→ guest
→ envd readiness
```

不要只测 Firecracker 本身。

## 12. Snapshot Resume 慢

观察：

- local snapshot cache；
- object storage；
- background download；
- P2P；
- layer depth；
- Host Page Cache；
- local NVMe。

## 13. Proxy 401/403

先确认 Credential 面：

```text
management API → X-API-Key
private ingress → traffic access token
secure envd → X-Access-Token
```

## 14. Sandbox 无法访问内网

可能是预期的安全策略。检查：

```text
always_denied_cidrs
allowOut
denyOut
allow_internet_access
domain allowlist
```

## 15. 多节点“创建后找不到”

重点排查：

```text
sandbox binding
Redis
Scheduler
Gateway
node health
static discovery / EndpointSlice
```

## 16. Benchmark 设计

至少区分：

```text
cold start vs warm snapshot
cache cold vs hot
single vs concurrent
small vs large image
small vs large memory
p50/p95/p99
fork throughput
snapshot latency
steady-state block I/O
delete/cleanup
single-node vs distributed
```

## 17. 故障演练

主动测试：

```text
kill node
kill gateway
kill scheduler
restart Redis
block object store
fill cache disk
restart host
expire API key
make artifact unavailable
```

基础设施能在失败情况下恢复，比 happy path 更重要。

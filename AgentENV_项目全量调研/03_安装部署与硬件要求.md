# AgentENV：安装部署与硬件要求

> 调研日期：2026-08-31  
> 范围：AgentENV 官方 `latest` 文档、GitHub `kvcache-ai/AgentENV` 主仓库与 Releases。  
> 版本提示：当前 GitHub 最新 tagged release 为 `v0.1.2`；`main` 分支 Rust workspace 已为 `0.1.3`。`latest/main` 中的内容不一定全部包含在 v0.1.2 二进制发布中。

## 1. 基础 Host 条件

- Linux Kernel 6.8+
- 标准路径需要 `/dev/kvm`
- ublk 能力
- 能运行 Firecracker
- Docker 路径需 Docker
- 源码构建需 Rust/Linux build 工具
- 多节点建议高速网络及共享/对象存储

检查：

```bash
uname -r
ls -l /dev/kvm
egrep -c '(vmx|svm)' /proc/cpuinfo
lsmod | grep ublk
```

## 2. Windows/macOS

Runtime 强依赖 Linux/KVM/ublk/network namespace，因此 Windows/macOS 不是标准 Runtime Host。CLI 可在支持平台使用，但 Sandbox Node 应部署在满足要求的 Linux 机器。

Windows 用户更现实的方式：

- Linux 服务器；
- 支持 nested virtualization 的 Linux VM；
- 裸金属/可用 KVM 云实例；
- 特定云环境评估 Experimental PVM。

不要默认 WSL2 能完整满足所有内核能力，需实测。

## 3. Quick Start

最小闭环：

```text
安装 Runtime
→ 获取 API Key
→ pull ubuntu:24.04
→ start
→ exec/connect
→ snapshot
→ delete
```

单节点 API 常用 `127.0.0.1:8000`。

## 4. Docker 单节点

适合 Demo、开发、单机验证。Docker 只是封装 AgentENV Node，Sandbox 本体仍是 Firecracker microVM。

Host 仍需要 KVM、ublk 和必要 privilege/capability。

## 5. Docker Compose 多节点模拟

单 Host 模拟：

```text
Gateway
Scheduler
Node 1
Node 2
...
```

用于验证 scheduling、binding、routing、node failure、多节点 API。项目提供类似 `make deploy-up` 的工程入口，具体以当前 tag 为准。

## 6. Static Multi-Node

```text
Gateway :8080
Scheduler :9090
Node A :8000
Node B :8000
```

Scheduler 使用静态 Node 列表。简单但节点变化不自动发现。

## 7. Kubernetes

典型：

```text
Gateway       → Deployment + Service
Scheduler     → Deployment
AgentENV Node → privileged DaemonSet
Discovery     → Headless Service / EndpointSlice
```

调度粒度不同：

```text
Kubernetes 管 AgentENV Node
AgentENV Scheduler 管 Sandbox
```

## 8. Shared Storage

多节点 Snapshot 需要跨节点可见。

- POSIXFS：NFS/共享文件系统等
- OSS/S3-compatible：云对象存储

## 9. 网络

On-demand image/snapshot 对网络敏感。官方建议至少约 1Gbps，高并发大规模场景推荐 10Gbps+。

启动时延可能受 Registry、Object Store、cache miss、local disk，而不只是 Firecracker 本身。

## 10. PVM

用于部分无法 nested KVM 的云环境，当前 Experimental。

关注：

- x86_64；
- PVM-capable Host Kernel；
- Host/Guest ABI；
- PVM Firecracker/Guest Kernel；
- 安全补丁与兼容性。

标准 KVM 可用时应优先 KVM。

## 11. 源码构建

通常需要：

```text
Linux >= 6.8
Rust
Go（services）
build-essential
protobuf/gRPC build chain
KVM/ublk
sudo/root setup
```

常见入口：

```bash
make
make release
```
